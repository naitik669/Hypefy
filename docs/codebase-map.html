There is no state library, no ORM, and no component library. State is React state plus Supabase Realtime; data access is the Supabase client directly; components are hand-written on Tailwind tokens. If you are looking for Redux or Prisma, they are not missing — they were never here.

Architecture

The shape of it

One codebase, three runtimes. The single most useful thing to understand on day one is that the Android app is not a separate build — it is a native shell whose WebView loads the live website.

Browser
hypefy.chat — the PWA, service worker, web push
Android shell
Capacitor WebView pointed at the same URL, plus native plugins
Vercel
Next.js server — RSC, API routes, auth proxy
Supabase
Postgres + RLS, Auth, Storage, Realtime, pg_cron
Why this matters

capacitor.config.ts sets server.url = https://www.hypefy.chat. So a Vercel deploy updates every installed app instantly — no store review, no OTA service. Only changes to the shell itself (plugins, permissions, manifest, icons) need a new APK.

Request path

src/proxy.ts is the entry point. In Next 16 "Proxy" is the renamed Middleware: it runs before every non-static request, refreshes the Supabase session cookie, and redirects unauthenticated users away from protected routes. The real work lives in src/lib/supabase/middleware.ts.

Route groups carry the layout split: (app) is the signed-in shell with bottom nav, (auth) is sign-in and sign-up, (legal) is static policy pages. The root page.tsx is a smart router — logged out goes to onboarding, incomplete profile to setup, otherwise home.

Layer · Client

Frontend

Server vs client components

Pages are Server Components that fetch with the server Supabase client and pass plain props down. Anything interactive is a "use client" component underneath. The pattern to copy: page.tsx queries and shapes, the client component renders and mutates.

Shared UI

src/components/ui/ holds the primitives worth knowing before you build anything: BottomSheet, CenterModal, ConfirmDialog, FloatingMenu, ZoomViewer, Avatar, ToastProvider. All overlays share an open / onClose pair, which is what lets the Android back button dismiss them (src/lib/overlay-stack.ts).

Vocabulary

The product has its own words, and they are used literally in code: Hype = like · Shot = short video reel · Show = 24-hour story · OneShot = view-once photo · Note = short status your circle sees · Discover = explore.

Layer · Data

Data access

There are three Supabase clients and picking the wrong one is the most common early mistake.

ClientFileWhen
Browser lib/supabase/client.ts Client Components. Writes the session to cookies, so the server sees it too. Runs as the user, under RLS.
Server lib/supabase/server.ts Server Components, Route Handlers. Also the user, also under RLS.
Service role created inline in API routes Bypasses RLS entirely. Only in /api/*, only where a user genuinely cannot be the actor — push fan-out, OneShot delivery, Spotify tokens.
Security model

Every one of the 40 tables has RLS enabled. Authorization lives in Postgres, not in application code — so a missing policy is a locked door, not an open one. Sensitive tables (app_locks, spotify_accounts, rate_events) go further: RLS on with zero policies, plus REVOKE ALL from anon and authenticated, so PostgREST cannot read them at all. They are reachable only through SECURITY DEFINER functions.

Typed but not everywhere

database.types.ts is generated from the live schema and the browser client is typed with it. The server and service-role clients are not, which is why you will see any in some routes. Regenerate after every migration — and see the Gotchas, because regeneration wipes a hand patch.

The feed

Ranking is a pure function in src/lib/feed-rank.ts, deliberately extracted so it can be unit-tested away from the server component. It blends recency (decays over 48h), social proximity, engagement, interest overlap, and per-author affinity. It is one of the four things with tests.

Storage buckets

avatars, post-images, shot-media, show-media, chat-media are public-read. oneshot-media is private with an insert policy and no select policy — view-once photos are streamed by a service-role route that claims them atomically, so a second read finds nothing.

The rule for native code

Everything routes through src/lib/native.ts (isNative(), safeNative()) and no-ops off device. The same bundle serves the website, so a native call must degrade silently rather than every feature growing an if (isNative) branch.

Layer · Live

Realtime & media

Eight components subscribe to Supabase Realtime channels — messages, presence, typing, notifications, call signalling. There is no socket server; Postgres changes and broadcast messages are the transport.

Voice and video are WebRTC peer-to-peer, signalled over a Realtime channel. CallProvider handles 1:1; GroupCallProvider runs a full mesh, which is why group calls are capped — every participant holds a connection to every other. TURN credentials come from NEXT_PUBLIC_TURN_*.

Music is 30-second preview clips from the iTunes Search API via /api/music. Spotify was evaluated and is parked, not deleted — the routes and SDK wrapper remain, unreachable from the UI. docs/BACKEND.md records why, so nobody repeats the investigation.

Ops

Build & ship

Two independent pipelines, because there are two update channels.

ChangeShips viaSpeed
Pages, UI, API routes — nearly every commitVercel deployInstant, app included
Plugins, permissions, manifest, icons.github/workflows/android.ymlNew APK

ci.yml runs lint (non-blocking), typecheck, unit tests and the Next build. android.yml runs on every push to main: Capacitor sync, Gradle release build, artifact upload, then Firebase App Distribution.

Version numbers come from git — versionCode is the commit count, versionName the short SHA — so builds are always unique and monotonic with no manual bookkeeping. Signing reads from environment variables and falls back to the debug key when unset, so a local release build still works.

Gotchas

Things that have already cost someone an afternoon.

Regenerating types wipes a patch

create_group's p_title is nullable in SQL but the generator infers it as required. The fix is hand-applied in database.types.ts with a comment saying so — re-apply it after every regeneration.

REVOKE from anon alone does nothing

Postgres grants EXECUTE to PUBLIC by default and anon inherits it. Revoke from PUBLIC, then grant back to authenticated. Migration 0027 exists because of this.

Line endings are CRLF

Scripted multi-line find-and-replace with \n silently matches nothing. Use an editor, or handle \r\n. Related: gradlew lost its executable bit from a Windows checkout and failed CI with an opaque exit code 126.

Lint has a known baseline

Lint is non-blocking in CI because of pre-existing debt. Don't expect zero — compare the error count before and after your change, and keep it flat.

Two more

secrets cannot be used in a GitHub Actions if: — lift them into env first, or the whole workflow fails before any step runs.

legacy-peer-deps lives in .npmrc so local installs and npm ci resolve identically. Leave it there.

Getting started

Run it locally

npm install
cp .env.example .env.local   # fill in Supabase URL + keys
npm run dev                  # http://localhost:3000

Only NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are needed to boot. The rest degrade gracefully: no VAPID keys means no push, no Giphy key means no GIF search.

CommandDoes
npm run devNext dev server
npm run typechecktsc --noEmit — run before every commit
npm testVitest
npm run cap:syncPush web + plugin changes into the Android project
npm run cap:androidOpen Android Studio
Building the app

You need a JDK and the Android SDK — Android Studio brings both. You usually don't: every push to main produces an installable APK as a GitHub Actions artifact, which is faster than building locally.
